# math---postgraduate---plan
我的数学专业考研规划
| 知识内容 | 需求工程 | 设计工程（非技术部分） |
|----------|----------|----------------------|
|          | Ⅰ. 需求调研 | Ⅱ. 需求分析 | Ⅲ. 概要设计 | Ⅳ. 详细设计 | Ⅴ. 应用设计 |
| 1. 定位 | ■ 自我定位：信息与计算科学专业在读学生，已取得四六级、普通话、计算机二级证书，目标为攻读数学专业研究生<br>■ 明确考研涉及的数学学科考查范围与重点，认知自身知识储备与目标院校要求的差距 | ■ 宏观规划：覆盖基础、强化、冲刺全阶段，明确各阶段知识构建、解题能力、时间管理目标<br>■ 设计思想：以"夯实基础-提升能力-模拟应试"为核心 | ■ 应用构造：结合专业知识设计学习场景，如用数值计算迭代思想理解数分极限<br>■ 应用架构：整合资源（基础用教材+网课，强化用专题+习题，冲刺用真题）<br>■ 时间分配：基础（数分2h、高代2h、概率论1h/天），强化（数分2.5h、高代2.5h、概率论1.5h/天）<br>■ 机构选择：自主学习为主，难点辅以辅导班/线上课 | ■ 应用细化：<br>- 数分极限：每天1h，结合牛顿迭代法（专业）练习证明题<br>- 高代特征值：每天1.5h，结合PCA降维（专业）理解应用<br>- 概率论分布：每天1h，结合蒙特卡洛模拟（专业）理解场景<br>■ 架构优化：每周评估进度，动态调整各科时间分配 | ■ 应用落地：<br>- 时间管理：番茄工作法（25分钟专注+5分钟休息）<br>- 资源使用：真题按知识点分类练习，错题标注专业关联<br>■ 定期回顾专业知识与考研数学的结合点 |
| 2. 功能 | ■ 知识需求：掌握数分（实数理论、级数）、高代（多项式、线性变换）、概率论（随机变量、分布）核心知识点<br>■ 业务需求：满足考研应试要求，能准确高效解题<br>■ 功能需求：获取资源、制定计划、高效学习、模拟测试分析能力 | ■ 业务功能规格书：<br>- 基础：通读教材，整理笔记标专业关联点<br>- 强化：专题突破+刷题<br>- 冲刺：真题模拟+错题总结<br>■ 分活：每日定量刷题，用思维导图和错题本辅助学习<br>■ 功能矩阵：基础（知识80%+解题20%），强化（知识40%+解题60%），冲刺（知识20%+解题80%） | ■ 功能应用规格书：思维导图标专业应用，错题本按知识点分类标专业关联<br>■ 业务功能规格书（组件+件数）：<br>- 数分：极限（5件）、积分（4件）、级数（3件）<br>- 高代：矩阵（4件）、线性变换（3件）、多项式（2件）<br>- 概率论：随机变量（3件）、数字特征（2件）<br>■ 系统功能：每天学习≥3小时，自主安排内容与时间 | ■ 功能深化：<br>- 数分级数：细分类型，总结判别法，结合函数近似展开（专业）分析<br>- 高代线性变换：结合不同基分析矩阵变化，用图形学案例理解<br>- 概率论分布：对比离散/连续计算差异，结合信号处理场景理解<br>■ 系统功能调整：按精力分配学习时间，上午学数分，下午/晚上学高代/概率论 | ■ 功能拓展：<br>- 综合训练：每周2小时跨科目练习，强化专业与考研融合<br>- 碎片化学习：Anki记公式和易错点，关联专业应用场景 |
| 3. 数据 | ■ 实体设置：数学知识实体（含专业关联）、学习资源实体、学习计划实体、测试成绩实体<br>■ 实体关系：资源支撑知识学习，计划指导资源与知识结合，成绩检验知识掌握程度 | ■ 数据概要规格书：涵盖知识掌握程度（含专业关联）、学习时间、资源使用、成绩数据<br>■ 数据分类：按科目和类型分类<br>■ 数据规范：知识掌握用"理解-掌握-熟练运用"描述，时间单位"小时"，成绩值域0-150分<br>■ 主数据规范：核心知识点编码（如MathAna-Limit-SeqLimit-CS） | ■ 数据详细规格书：成绩含专业关联题型得分，时间记录到分钟（标专业回顾时长）<br>■ 数据关系图：知识实体-成绩实体关联，计划实体-时间实体关联<br>■ 数据格式：计划编号"MathPlan-科目-阶段-序号-CS"，成绩记录"日期|科目|分数|专业题型得分|排名"<br>■ 数据关联：时间与计划关联，分析计划执行/专业融合效果 | ■ 数据细化：<br>- 数分极限掌握度：结合数值迭代理解，标"理解-掌握-熟练运用"<br>- 学习时间：Forest记录专注时长，标专业回顾时间<br>- 测试成绩：记录专业关联题型得分，分析专业助力效果 | ■ 数据应用：每周用Excel做折线图，分析学习时间/专业关联时长与成绩的关系<br>■ 动态调整：时间投入多但成绩差则调整学习方法 |
| 4. 性能 | ■ 暂未明确具体性能指标，后续结合设计工程补充 | ■ 质量要求：计划合理、资源优质、方法高效<br>■ 效率指标：基础阶段完成3科教材学习，强化阶段掌握80%专题，冲刺阶段真题正确率≥70% | ■ 数据模型：建立"学习输入-知识掌握-测试输出"模型<br>■ 业务模型：用模型制定管理规划、判断学习状态<br>■ 保证机制：数据质量保证、方法验证<br>■ 应用价值：架构保障科目均衡推进，资源架构快速获取优质资源 | ■ 保证强化：记录错题知识点/原因，同一知识点多次错则换学习方式<br>■ 效率优化：根据掌握程度调整学习重点，优先攻克薄弱环节 | ■ 应用价值提升：优化资源渠道，按阶段调整时间分配<br>■ 效果评估：每月对比模拟测试成绩，检验学习效果提升情况 |
| 5. 文本/资料/交付 | ■ 调研材料：考研大纲、目标院校历年真题、参考教材、学长经验帖<br>■ 论证资料：目标院校选择、学习计划初步方案的论证文档 | ■ 需求规格说明书：详细说明知识掌握、进度、应试能力需求<br>■ 需求4件套：调研文档、分析报告、规格说明书、跟踪矩阵 | ■ 概要设计规格书：说明阶段划分、核心任务、学习策略<br>■ 业务模型图：资源获取→知识学习→测试检验流程<br>■ 业务规划图：各阶段学习重点<br>■ 数据规范库：知识编码、数据记录规范 | ■ 详细设计规格书：说明每周/每天任务、时间分配细则<br>■ 数据件：Excel记录时间，数据库管理成绩<br>■ 业务4件套：详细设计文档、流程说明、操作规范、验证标准<br>■ 数据蓝图：数据产生→流转→应用环节 | ■ 详细设计落地：每周列每日任务，标注完成情况<br>■ 交付成果：每月整理错题本、思维导图、成绩分析报告，形成月度文档 |
